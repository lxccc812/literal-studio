# 公开仓库约定

仓库内容和 Git 提交元数据使用通用项目身份，不包含个人信息。

## 首次开发

在仓库根目录运行：

```sh
sh scripts/setup-public-git.sh
```

Windows 使用 Git 自带的 Git Bash，或在 PowerShell 中调用 Git 的 `sh`。不需要安装新的开发环境。
脚本只设置当前仓库的提交身份和 `.githooks` 路径，不改变全局 Git 配置。
Git 不会在 clone 后自动启用仓库内的 hooks，每个新的 clone 都需要执行一次设置。

提交前检查完整暂存区、提交说明中的本机绝对路径、用户目录、非虚构邮箱及作者/提交者身份；推送前检查全部可达历史的文件、提交说明及身份。
手动检查命令：

```sh
sh scripts/check-public-content.sh --staged
sh scripts/check-public-content.sh --revision HEAD
sh scripts/test-public-content.sh
```

## 内容规则

- 路径示例使用仓库相对路径，不写开发者的盘符、用户名或实际目录。
- 插件 ID、Vendor 和许可证使用项目标识，不使用个人姓名或账号。
- 示例邮箱只能使用明确虚构的 `example.com`、`example.org`、`example.net` 或 `.invalid` 域名。发布联系渠道使用项目公共渠道，并在添加前单独审核。
- 需求与验证记录描述软件行为、固定版本和可复现命令，不记录个人设备详情、IDE 许可、私人项目或账号。
- 不提交真实输入数据、截图中的账号或许可、原始诊断日志、凭据和个人联系方式。
- 自动检查是补充措施：个人姓名、账号、图片、二进制、电话号码或特殊编码仍需人工审核，不能承诺自动检测所有个人信息。
- 常规检查不扫描未跟踪的构建缓存，也不将其提交。新增二进制只允许经过来源和内容审核的项目资源。

## 历史处理

普通修改不会删除旧提交中的内容。发现已推送的个人信息后，需要先审查清理后的文件与提交身份，再单独确认改写远程历史。
不得未经确认强制推送，也不得将清理当前文件视为已经清理旧历史。
