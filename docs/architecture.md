# 架构设计

## 模块职责

`core` 是独立 Kotlin/JVM 模块，后续负责词法分析、语法解析、格式识别、统一节点模型、校验与各格式输出。
`plugin` 依赖 `core`，负责 Tool Window、输入输出编辑器、操作按钮、设置与 IDE 生命周期。

当前只建立模块和依赖关系，尚无业务类、解析器或界面代码。

## 数据路径

```text
输入文本 + 输入格式选择
        ↓
对应解析器 / 自动识别
        ↓
统一结构模型 + 原始位置 + 诊断
        ↓
目标格式校验 → 格式化输出 / 错误提示
```

自动检查和手动检查共用相同服务；格式化与转换共用统一节点模型，避免每一对语言分别维护转换逻辑。
节点保留成员顺序和数字词面/精度；成员集合不能先写入普通 Map 而丢掉重复 key。

## 解析与 IDE 边界

- 不使用 eval、不执行表达式，不借助全局正则替换解析字符串和语法。
- 不强制依赖 Python、JavaScript 专用 IDE 插件；解析核心不因使用 PyCharm/WebStorm 而变化。
- UI 计划采用平台原生组件与可调整的纵向分割布局；无需 JCEF、WebView 或前端运行环境。
- EDT 只读写界面，后台线程处理输入；使用输入修订号和取消机制丢弃过时结果。
- 编辑器、监听器与后台任务挂靠 IDE Disposable，工具窗口关闭或项目释放时统一清理。

## 构建与兼容

- 使用官方 IntelliJ Platform Gradle Plugin 2.x；JDK、Gradle 与编译器只在 Docker 中运行。
- Kotlin 标准库由 IDE 提供，核心仅 compileOnly 引用，避免重复打包。
- 当前按 PyCharm 262 分支固定 SDK 与兼容范围；后续通过 Plugin Verifier 和真实 IDE 验收扩大范围。
- 图形界面验收在已有 IDE 中安装容器生成的 ZIP 完成。本阶段不配置 Linux 图形容器或 GUI 远程服务。
