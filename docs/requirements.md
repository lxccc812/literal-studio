# 初版需求

## 阶段边界

本次只搭建工程、构建环境和文档，不实现业务功能。以下均为后续实现的验收依据。

## 输入与输出

- 上方为输入编辑器，下方为输出编辑器，采用可调整高度的纵向双区布局。
- 输入区可编辑；输出区默认只读，支持选择与复制。
- 显示检测出的输入格式，以及可选择的目标输出格式。
- 自动模式遇到多个解析器都能接受的输入时，使用 JSON → JS/TS 字面量 → Python 的确定顺序，并允许手动切换。不要宣称能唯一判断原始语言。
- 输入停止约 400 ms 后在后台执行检查和格式化；自动结果与手动结果保持一致。
- “格式检查”只检查并展示结果；“格式化”在下方输出结果，不修改上方原文。
- 输出格式默认为检测到的格式，可切换为 JSON、JS Object/Array 或 Python dict/list。
- 解析失败时输出区不继续展示看似对应当前输入的旧结果；保留输入并提示错误位置及原因。

## 输入语法边界

- JSON：严格 JSON 语法，包含 object、array 与 JSON 标量。
- JS/TS：数据字面量子集，包含 object、array、字符串、数字、boolean、null；支持合法的未引号属性名、单双引号、注释和 trailing comma。
- Python：dict/list 数据字面量子集，包含字符串、数字、True/False/None；支持单双引号、注释和 trailing comma。
- JS 未引号的 value 是变量引用，不应自动解释为字符串；Python 变量引用同样不求值。
- 不混用 Python 与 JS 的关键字。不能将混合语言片段当作自动修复输入。
- 首版不处理完整程序、赋值声明、TS 类型声明、函数调用、展开表达式、推导式、模板插值、set、tuple、bytes 或调试器专有对象表示。
- 不执行 Python/JavaScript，不启动外部解释器。

## 转换规则

- 三类格式的共同数据类型双向转换：object/dict、array/list、string、number、boolean、null/None。
- 默认保持成员顺序，不排序 key。
- 数字避免经 double 中转而丢失精度；向 JS 输出超出安全整数范围的值时明确提示风险。
- Python 的非字符串标量 key 可以在 Python 格式中保留，但转换为 JSON/JS 时明确报错，不自动字符串化。
- 重复 key、NaN/Infinity、undefined 等不能无损映射的内容，首版明确报错，不静默覆盖或替换为 null。
- 格式化可规范化引号和移除语法注释，但不承诺源码注释或词面形式的无损还原。
- 字符串内部的引号、反斜杠、换行、Unicode 与类似 True/None 的文字必须保持原本值。

## 非功能要求与验收

- 处理完全在本地完成；不发送输入、收集遥测或自动保存输入历史。
- 输入变化时取消或废弃旧任务，旧结果不能覆盖新输入的结果。
- 控制输入大小、深度、节点数与任务时间，避免大型输入阻塞 IDE。
- 检查嵌套结构、顶层 list/array、转义字符串、语言常量、尾逗号、错误行列和跨格式往返。
- 首个界面验收目标为 PyCharm 2026.2.0.1；其他产品和版本逐项记录真实验证结果。
